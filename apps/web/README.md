# Replicant web application

The Vite development server proxies `/api` and `/ws` to `replicantd` on
`127.0.0.1:8080`.

```sh
# Terminal 1, from the repository root
RS_API_TOKEN=... cargo run -p replicant-server --bin replicantd

# Terminal 2
cd apps/web
npm install
npm run dev
```

## Structure

Flat by design — page components live directly in `src/`, each with a colocated
`*.test.tsx`.

| File | Role |
| --- | --- |
| `App.tsx` | Application shell and page routing. |
| `daemon.tsx` | WebSocket connection to `replicantd` and delta application. |
| `protocol.ts` | Parsers for the `replicant-protocol` DTOs. |
| `api.ts` | Typed HTTP calls to `/api`. |
| `shellState.ts`, `domainQuery.ts` | Shell state and page-data querying. |
| `*Page.tsx` | One component per navigation destination. |
| `wasm/galaxy_renderer/` | Generated by `make galaxy-wasm`. Ignored by Git; rebuilt by `dev`, `build`, and `check`. |

Page data comes from typed projection endpoints, not raw JSON assembled in the
browser. The frontend store is a **disposable projection** — never
authoritative. `replicantd` owns truth.

## Checks

```sh
npm run check      # or: make web-check   (from the repository root)
```

`check` runs the WASM build, format check, lint, tests, and the production
build. Individual scripts: `format`, `format:check`, `lint`, `test`,
`build:web`.

Every script that touches the app runs `wasm:build` first, which shells out to
`make -C ../.. galaxy-wasm`. A missing `wasm-pack` will fail `npm run dev`
before Vite starts.

## Provenance

The theme colors, application-shell layout, and command-palette interaction
were adapted from the approved `replicant.react` source supplied by its author
and used with the permission provided by the user. Backend behavior was not
copied: this application uses the typed `replicantd` HTTP/WebSocket protocol.
